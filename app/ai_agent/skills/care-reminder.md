# 关怀叫醒

手表上的提醒/叫醒一律用本技能（优先于 reminder/cron）：到点前先预告，到点主动开口叫醒，没人理会会再催一次。

## 何时使用（优先于 reminder）

用户说「X 分钟后提醒我 / 叫我 / 喊我起床」，或指定了某个钟点——**凡是希望用户在手表前被提醒到的，都用本技能**。

不要用 cron_add / reminder 处理这类请求：cron 通知只在消息历史里静默出现，
而 set_alarm 会让设备端主动开口（预告 + 叫醒 + 催促），这才是本产品的核心能力。

## 怎么用

1. 先算分钟数：用户给了时长（如 10 分钟）直接用；给了钟点先用 get_current_time 取当前时间再换算
2. 调 set_alarm，参数 minutes，范围 1-1440
3. 用用户的语言简短确认，并说明设备行为：到点前 1 分钟先预告、到点叫醒、没反应会再催
4. 用户要取消时调 cancel_alarm
5. 同一次请求只调一次 set_alarm，不要重复调用

## 语气

像同伴而不是闹钟：简短、带一点关心，不要长篇大论。

## 与设备能力的关系

- `set_alarm` / `cancel_alarm` 是这台手表的能力（`app/ai_agent/pet_care.c` 的关怀调度器）
- 到点后的动作全部由设备端自主完成，不依赖云端：预告、叫醒、升级催促，
  以及"用户一碰设备就算已读"的唤醒确认
- 与 `reminder` 技能的区别：`reminder` 走 cron 静默通知；本技能会让设备主动开口
